## 实现的功能

重写了 `sys_get_time` 和 `sys_trace`：先按页把用户虚拟地址翻译成物理地址再读写，`TimeVal` 跨页时分段写入；`sys_trace` 读写前检查页表项有效、带 U 且有相应权限。系统调用计数放在 TCB 中，创建任务时初始化。实现了 `mmap` 和 `munmap`，`prot` 左移一位并加 U 作为页面权限，逐页检查映射，取消映射时释放页帧。选做实现了惰性分配和三种置换算法。

## 选做：惰性分配与页面置换

### 设计

置换算法放在独立的 `page-replace` crate 中，`no_std`，不依赖内核。它定义了两个 trait：

- `Pages`：一个地址空间里驻留页面的视图，提供读取访问位和修改位、清除访问位、写回 swap 三个操作。
- `Replacer`：置换策略。页面调入时调用 `insert`，每个时钟中断调用 `tick`，两者都返回需要换出的页。

crate 中有三种实现：

- `Clock`：改进的 Clock 算法，属于局部置换，每个地址空间的帧数固定。指针按 (A, D) 扫描：(0, 0) 直接换出，(0, 1) 先写回再清 D，(1, x) 清 A。
- `WorkingSet`：工作集算法。每个时钟中断采样一次访问位，记录页面最近一次被访问的时间，超过窗口 Δ 未被访问的页面被换出。
- `PageFaultFrequency`：缺页率算法。如果距上次缺页超过 T，就换出这段时间内未被访问的页面，否则只调入缺失页。每次缺页后清除所有访问位。

内核侧的改动：

- `MemorySet` 新增 `lazy` 表，记录 mmap 页面的权限、当前物理帧和 swap 槽位。`mmap` 在惰性模式下只登记，不分配物理帧。
- `trap_handler` 收到三类 page fault 时调用 `handle_page_fault`。如果地址落在 lazy 表里且权限允许，就分配帧；该页之前被换出过的，再从 swap 读回内容；然后建立映射并交给置换策略，返回用户态重新执行出错的指令。其他情况仍然杀死应用。
- 内核通过物理地址访问用户内存，不会经过用户页表，所以 `sys_write`、`sys_get_time` 和 `sys_trace` 访问用户缓冲区前先调用 `fault_in`，把相关页面调入并设置 A/D 位。
- swap 设备用内核堆上的页大小缓冲区模拟。干净的页面换出时不需要写回：要么从未写过，内容全零；要么与上次写回的槽位一致。

策略在编译时通过环境变量 `PAGE` 选择。不设置时 mmap 立即分配，与必做部分的行为相同，评测也使用这种模式。

```sh
PAGE=lazy  make -C os run   # 惰性分配
PAGE=clock make -C os run   # 惰性分配 + 改进的 Clock，每个任务 16 帧
PAGE=ws    make -C os run   # 惰性分配 + 工作集，Δ = 4 个时钟中断
PAGE=pff   make -C os run   # 惰性分配 + 缺页率，T = 2 个时钟中断
```

### 测试

- 库的单元测试：`cd page-replace && cargo test`。测试里用一个模拟 MMU 维护 A/D 位，共 8 个用例，覆盖 Clock 的帧数上限、优先换出干净页、第二次机会、跳过已 munmap 的页，工作集的窗口淘汰和阶段切换，缺页率的扩张与收缩。全部通过。
- 内核测例在 `tests/ch4/`，复制到 `user/src/bin/` 后运行：
    - `ch4x_lazy` mmap 256 MiB，超过 QEMU 的 128 MiB 物理内存，抽样读写其中 16 页，并让 `sys_get_time` 和 `sys_trace` 访问从未被触碰的页面。只有惰性分配能通过；不设置 `PAGE` 时会耗尽物理页帧。
    - `ch4x_swap` mmap 66 页，先循环写 64 页三轮，再分两个阶段分别反复写 8 页，最后检查所有页面的内容。
- 四种 `PAGE` 取值下，`BASE=2 TEST=4` 的全部测例加上这两个测例均通过。不设置 `PAGE` 时，官方评测 16/16 通过。

`ch4x_swap` 退出时内核打印的统计如下：

| 策略 | 缺页 | 换入 | 换出 |
| --- | --- | --- | --- |
| lazy | 66 | 0 | 0 |
| clock（16 帧） | 460 | 394 | 444 |
| ws（Δ = 4） | 123 | 57 | 57 |
| pff（T = 2） | 114 | 48 | 48 |

循环访问 64 页时，16 帧的 Clock 每轮都要换遍所有页面，这正是固定帧数局部置换的弱点。工作集和缺页率两种算法让驻留集随访问情况伸缩：64 页的循环阶段全部驻留，切换到 8 页的阶段后再把不用的页面换出，所以缺页次数少得多。

## 简答作业

### 1. SV39 页表项的组成

页表项共 64 位：

| 位 | 字段 | 说明 |
| --- | --- | --- |
| 63–54 | 保留 | 必须为 0（Svpbmt、Svnapot 等扩展会使用其中几位） |
| 53–10 | PPN | 44 位物理页号，分为 PPN[2]（26 位）、PPN[1]（9 位）、PPN[0]（9 位） |
| 9–8 | RSW | 留给操作系统使用，硬件忽略 |
| 7 | D | Dirty，页面被写过 |
| 6 | A | Accessed，页面被访问过 |
| 5 | G | Global，所有地址空间共享该映射，切换 ASID 时不必刷掉 |
| 4 | U | 用户态能否访问。S 态默认不能访问 U 页，除非 `sstatus.SUM` 置位 |
| 3 | X | 可执行 |
| 2 | W | 可写 |
| 1 | R | 可读 |
| 0 | V | 有效位，为 0 时其余位都不被硬件解释 |

R、W、X 全为 0 表示这一项指向下一级页表，否则是叶子项。W 为 1 而 R 为 0 是保留组合。A 和 D 由硬件设置，或者在访问时触发 page fault，交给软件设置。

### 2. 缺页

可能由缺页导致的异常是 Instruction Page Fault（12）、Load Page Fault（13）和 Store/AMO Page Fault（15），分别对应取指、读和写。

发生缺页时，`scause` 是上面的异常号；`stval` 是出错的虚拟地址；`sepc` 是出错指令的地址，处理完不加 4，`sret` 后重新执行这条指令；`sstatus.SPP` 记录出错前的特权级，用户程序出错时为 U。

Lazy 策略的好处是：程序启动快，不需要一次性加载和映射全部内容；没有用到的页面不占内存，也不产生加载和建表的开销；物理内存不足时也能申请较大的虚拟空间。

10 GiB 共 10 × 2¹⁸ ≈ 2.6 × 10⁶ 页。每个叶子页表项 8 字节，叶子页表约 20 MiB；上一级只需约 5120 项，即 10 个页表页，根页表 1 页，可以忽略。合计约 20 MiB，数量级是 10⁷ 字节。

实现 Lazy 时，mmap 只记录区间和权限，不分配物理页，也不写页表。缺页时内核用 `stval` 查找所属区间：找不到或权限不符就杀死进程；否则分配物理页并清零（文件映射则从磁盘读入），建立映射，返回用户态重新执行出错的指令。本实验的选做部分就是这样实现的。

swap 时，页面被换出后页表项的 V 位清 0，访问时触发缺页。由于 V 为 0 时硬件不解释其余位，操作系统可以把页面在磁盘上的位置（swap 槽位号）存在剩下的位里，缺页时据此把页面读回。

### 3. 双页表与单页表

**单页表如何更换页表**：只有切换进程时才需要换表。写入新进程的 `satp`，再执行 `sfence.vma`；使用 ASID 时可以不刷掉全部 TLB。

**如何阻止用户态访问内核页面**：内核页面的页表项不设 U 位。U 态访问 U 为 0 的页面会触发 page fault。

**单页表的优势**：trap 进出时不需要切换 `satp` 和刷新 TLB，开销小；内核可以直接通过用户虚拟地址访问用户缓冲区，不必像本实验一样先查用户页表再按物理地址访问；也不需要跳板页这类专门处理换表的机制。

**双页表何时换表**：每次从用户态 trap 进内核时（`__alltraps` 中切到内核页表），以及每次返回用户态时（`__restore` 中切回用户页表）。任务切换本身发生在内核里，用的都是内核页表，不需要换表，但返回用户态时会换成新任务的页表。如果写单页表操作系统，我会在调度器切换到另一个进程时换表，也就是 `__switch` 之前或之后写 `satp`。同一进程内的 trap 和系统调用都不换表。
